# 淘宝/天猫商品活动异常监控（钉钉报警版）

参考“拼多多活动下线监控 V8.1”的架构，面向淘宝/天猫（千牛卖家中心）改造的多店铺活动异常监控工具。
定时用 Playwright 打开各店铺的“活动报名记录”页面，逐个查询白名单商品，识别异常后自动推送钉钉群。

## 监测的三类异常

| 异常类型 | 判定逻辑 |
|---|---|
| 活动下线/被清退 | 报名记录中出现“活动下线/清退”（offlineWords），且没有更晚的“报名成功/审核通过”（successWords）接替。支持监控时间范围、活动关键词过滤、恢复容差分钟数 |
| 商品从活动中消失 | 页面正常响应查询，但报名记录中查不到该商品 ID（页面显示“暂无数据/共 0 条”等空结果标识，或查询后全页无该 ID）。页面本身加载失败不会误判为消失 |
| 活动价/库存异常 | 以最新的“报名成功/进行中”记录为基准行，提取页面活动价、库存，与白名单登记的 `expectedPrice`、`minStock` 比对：价格不一致（超出容差）或库存低于下限即报警 |

异常持续期间按 `anomalyRepeatMinutes`（默认 30 分钟，可在网页管理「重复提醒」输入框直接改）间隔重复提醒；**只有异常状态才发钉钉，恢复正常不发通知**（异常消失后自动停止提醒，仅写日志；如确需恢复通知，在 config.json 设 `"notifyProductRecovery": true`，店铺级恢复通知对应 `"notifyShopRecovery": true`）。

## 文件说明

```

```

## 部署步骤（Linux 服务器，2 核 4G 即可）

```bash
# 1. 解压上传后安装
cd ~
unzip -o taobao-activity-monitor.zip
cd taobao-activity-monitor
chmod +x *.sh
./install.sh ~/tb-monitor        # 安装到 ~/tb-monitor

# 2. 配置
cd ~/tb-monitor
node configure.js                # 交互配置店铺、商品白名单、检测间隔
# 编辑 config.json 填入钉钉机器人 webhook 和 secret（加签密钥）
node notification-test.js        # 验证钉钉能收到消息

# 3. 每个店铺登录一次（服务器无图形界面时，见下方“无界面服务器登录”）
node shop-login.js shop01

# 4. 手动跑一轮验证
node monitor.js --once

# 5. 安装为系统服务
./install-service.sh
./manage.sh status
```

## 浏览器模式（重要）

程序支持两种浏览器模式，由 config.json 的 `browserMode` 决定：

| 模式 | 适用场景 | 说明 |
|---|---|---|
| `builtin`（默认） | Linux 服务器 / 无界面环境 | 用内置 Chromium + 独立 profile，headless 运行；需要 `node shop-login.js shop01` 登录。淘宝风控对无头浏览器较敏感，会话可能几小时就失效 |
| `cdp`（Windows 推荐） | Windows 本机，装有 Chrome | 连接你自己打开的“监控专用 Chrome”窗口，会话保存在真实浏览器里，**不易被风控踢掉，不用反复扫码** |

### cdp 模式使用方法（Windows）

1. config.json 设置：
   ```json
   "browserMode": "cdp",
   "chromeDebugPort": 9222,
   ```
2. 双击 **`启动监控专用Chrome.bat`**：会为**每个启用店铺各打开一个独立的 Chrome 窗口**（每个店铺独立用户目录 `chrome-profile-<店铺编号>`、独立调试端口，登录态互不影响；与你日常浏览器也互不影响），**并自动对配置了账号密码的店铺逐个执行密码登录**——窗口里能看到自动填写过程，遇到滑块/短信验证时在对应窗口人工补一下即可。
3. 没配账号密码的店铺，在对应窗口里手动登录一次（建议让 Chrome“保存密码”）。之后掉线时监控也会自动重登，基本不用再管。
4. **保持这些窗口开着**（可以最小化），然后正常启动监控：`node monitor.js --once` 或 `node monitor.js`。
5. 监控每次检测会在对应店铺的浏览器里新开一个标签页，查完只关闭标签页，不会动你的浏览器和登录态。
6. cdp 模式下 `shop-login.js`、`profileDir`、`headless` 配置都不再需要（登录直接在窗口里完成即可）。
7. 多店铺窗口的调试端口默认从 9222 起依次递增；如需固定某个店铺的端口，在网页管理店铺卡片或 config.json 里设置该店铺的 `chromeDebugPort`。

> 为什么要单独一个“监控专用 Chrome”而不是直接用你日常的浏览器：Chrome 136 之后出于安全限制，禁止在默认用户数据目录上开启调试端口，所以必须用一个独立的数据目录。它用起来和普通 Chrome 完全一样。

## 免扫码：账号密码自动重登（可选）

在网页管理店铺卡片（或 config.json）里给店铺填上 **登录账号 `account` + 登录密码 `password`** 后：

- 监控发现“登录状态已失效”时，会**自动用账号密码尝试重新登录**，成功后继续检测，无需人工干预；
- 淘宝风控有时会要求滑块/短信验证：cdp 模式下监控专用 Chrome 窗口就在桌面上，程序会等待最多 `reloginChallengeWaitSeconds` 秒（默认 100 秒）让你在窗口里人工完成验证，完成后自动继续；
- 填了账号密码后，`node shop-login.js <店铺编号>` 也会先自动填写登录，你只需处理风控验证；
- 全局开关：`"autoRelogin": false` 可关闭自动重登。

> ⚠️ 注意：
> 1. 密码以明文保存在 config.json 中，请妥善保管该文件、不要外传或提交到公共仓库；
> 2. 网页管理的「登录密码」框不回显已保存的密码（留空=保持不变）；
> 3. 自动登录无法绕过淘宝风控本身——它的价值是“无风控时全自动、有风控时只需补一次验证”，不是 100% 无人值守；频繁自动登录也可能增加风控概率，建议 `intervalMinutes` ≥ 15。

## 网页管理后台（推荐，免命令行）

双击 **`启动网页管理.bat`**（或执行 `node admin-server.js`)，然后在浏览器打开：

```
http://127.0.0.1:3080
```

功能：

- **店铺与商品**：浏览器里直接添加/修改/删除店铺（店铺名、活动报名记录页 URL）和商品（商品ID、标题、活动名称、负责人、活动价、库存下限、监控开始时间、关键词等），改完点「保存全部修改」即写入 config.json，监控下一轮自动生效。「活动名称」支持**一键通用**：顶部输入框填好后点「应用到全部商品」一次填到所有商品，或每个店铺商品表下的「活动名称本店通用」只填本店；「活动报名记录页 URL」也支持**一键通用**：顶部输入框填好后点「活动URL应用到全部店铺」，一次填到所有店铺的「活动报名记录页 URL」栏（店铺层面；商品行的「活动页URL」一般留空即可，留空自动用店铺默认地址，仅当同一店铺同时参加多个活动时才需要给个别商品单独填）；
- **报警消息已精简**：钉钉异常消息以 markdown 卡片发送，只保留 店铺/商品ID/商品名称/活动名称/负责人/异常类型（及价格、库存、关键时间等动态信息），不再发送"下线详情/下线活动/监控模式/监控开始"等套话字段；**负责人一行红色高亮**；每次报警还会紧跟一条**纯文本 @ 提醒消息**（如「请负责人处理：@张三」，钉钉会把 @手机号 渲染成蓝色姓名）——钉钉的 markdown 消息里 @ 只显示蓝字、不触发"有人@我"强提醒（平台限制），所以 @ 单独走 text 消息可靠送达，同一人负责多个商品只 @ 一次。要真正 @ 到本人必须填其钉钉绑定手机号：在网页管理顶部「负责人手机号映射」框里按 `姓名=手机号` 每行一条填好（姓名须与商品表「负责人」一致），或直接改 config.json 的 `ownerPhones`；没配手机号的负责人只在消息里显示 @名字，不会真正提醒到本人；建议在网页管理里手工填好「活动名称」，否则报警里的活动名称会回退为页面识别文本（自动截断到 25 字）；
- **Excel 批量导入**：点「下载导入模板」获取 Excel 模板（含「活动页URL」列，支持多活动分别监控），按列填好后点「导入Excel」上传。同一店铺编号自动归类，同商品ID自动更新，新商品自动添加；示例行（商品ID 非纯数字）会自动跳过并提示；
- **检测状态**：查看最近一次每个商品的检测结果和运行日志，可点「立即检测一次（全部店铺）」手动全盘触发（运行中会出现「取消检测」按钮，误点后可随时中止，不用等全部店铺跑完）；每个店铺卡片上有「检测此店铺」按钮，只检测该店铺（结果与其他店铺的上轮结果合并显示，互不影响）；「停止自动检测」按钮可暂停按间隔的自动巡检（监控程序仍在运行，手动检测不受影响），点「恢复自动检测」后继续；
- 只监听本机 127.0.0.1，不会暴露到网络；钉钉密钥等敏感配置不在页面显示，保存时也不会被覆盖。

> 注意：网页管理的 Excel 导入功能依赖 xlsx 组件，首次覆盖更新文件后请在程序目录运行一次 `npm install`。

### 分享给同事一起用（局域网多人协作）

默认网页管理只能本机访问。要让同事也能打开并各自添加店铺/商品：

1. config.json 里加两项，然后**重启网页管理**（关闭黑窗口重新双击）：
   ```json
   "adminHost": "0.0.0.0",
   "adminToken": "设一个口令比如 tb2026"
   ```
2. 启动后黑窗口会打印 `局域网分享地址：http://192.168.x.x:3080`，把这个地址发给同事即可（首次打开 Windows 若弹防火墙提示，选“允许”）。
3. 同事打开后输入口令（adminToken），就能添加/修改店铺和商品；**保存后立即写入 config.json，监控下一轮检测自动生效，无需重启监控**。
4. 多人同时编辑有冲突保护：如果你保存时别人刚改过，页面会提示“配置刚被其他人修改”，刷新后再改即可，不会互相覆盖丢失。
5. 钉钉密钥、店铺登录密码等敏感内容不会在网页里显示，同事也看不到。

## 关键配置项（config.json）

```jsonc
{
  "intervalMinutes": 30,            // 检测间隔
  "anomalyRepeatMinutes": 120,      // 同一商品同一异常重复提醒间隔（0=每轮都报）
  "queryTimeoutSeconds": 30,        // 单个商品查询最长等待秒数（容忍网络卡顿）
  "emptyConfirmSeconds": 8,         // “暂无数据”需连续稳定该秒数才判定“商品消失”，防误报
  "errorAlertCooldownMinutes": 180, // 店铺级异常（登录失效等）冷却时间
  "autoRelogin": true,              // 掉线时用店铺账号密码自动重登（需店铺配置 account/password）
  "reloginChallengeWaitSeconds": 100, // 自动登录遇到滑块/短信时等待人工完成的秒数
  "offlineWords": ["活动下线", "清退"],      // 下线/清退关键词，可按后台实际文案调整
  "successWords": ["报名成功", "审核通过"],  // 恢复（报名成功）关键词
  "ongoingWords": ["报名进行中", "进行中"],  // 进行中状态词，用于价格/库存基准行
  "draftWords": ["草稿", "待完善", "待提交"], // 报名未完成状态词，商品能搜到但活动未生效，按异常报警
  "statusWhitelistMode": true,              // 状态白名单模式（推荐）：行状态不含正常词即报警
  "normalStatusWords": ["已发布设定", "报名成功", "审核通过", "报名进行中"], // 正常状态白名单
  "dingtalk": {
    "webhook": "https://oapi.dingtalk.com/robot/send?access_token=xxx",
    "secret": "SEC...",             // 机器人安全设置选“加签”时必填
    "atAll": false,
    "atMobiles": ["13800000000"]    // 可选，@指定负责人
  },
  "shops": [{
    "key": "shop01",
    "name": "XX旗舰店",              // 必须与后台显示的店铺名一致（防串店校验）
    "activityUrl": "活动报名记录页 URL",  // 登录后台后从地址栏复制
    "account": "",                   // 登录账号（可选）：掉线自动重登用
    "password": "",                  // 登录密码（可选）：明文存储，请保护好 config.json
    "chromeDebugPort": 0,            // cdp 模式该店铺的调试端口；0=从全局端口自动分配
    "products": [{
      "productId": "1234567890",
      "productName": "示例商品",
      "activityName": "天猫新势力周", // 活动名称，报警消息中显示，便于定位是哪个活动异常
      "activityUrl": "",             // 该商品的活动报名记录页 URL；留空=用店铺默认 activityUrl（多活动分别监控时填写）
      "activityDeadline": "2026-09-10", // 该活动的截止时间：截止前异常正常报警，过后自动停止该活动的一切报警；只写日期按当天 23:59 截止；留空=一直监控
      "owner": "张三",               // 负责人，报警消息中展示并 @
      "monitorMode": "added_time",  // signup_date=按报名时间 / added_time=加入名单后
      "monitorSince": "2026-08-01 00:00:00",
      "monitorActivityKeywords": "聚划算,百亿补贴",  // 只盯这些活动的下线，可选
      "recoveryActivityKeywords": "",               // 只认这些活动的报名成功，可选
      "recoveryGraceMinutes": 0,                    // 允许“先成功后下线”的容差分钟
      "expectedPrice": 99,          // 报名活动价；0=不校验价格
      "minStock": 100,              // 活动库存下限；0=不校验库存
      "priceTolerance": 0.01,
      "enabled": true
    }]
  }]
}
```

## 重要使用说明

1. **activityUrl 必须换成你自己的后台页面地址**。模板中的 `https://myseller.taobao.com/home.htm` 只是入口占位。登录千牛卖家中心后，进入“营销中心 → 活动报名 → 报名记录”（或淘营销平台“我的活动”），把地址栏 URL 填到店铺的 `activityUrl`。拼多多原程序也是同样的模式。
2. **一个店铺同时参加多个活动（按活动分类监控）**：给每个商品单独填 `activityUrl`（该商品所在活动的报名记录页地址）和 `activityDeadline`（该活动的截止时间），监控时按活动页自动分组、逐页分别检测，互不干扰。留空的商品使用店铺默认 `activityUrl`。三种填法都支持：网页管理商品表格的「活动页URL」「活动截止时间」列、Excel 导入模板、直接改 config.json。⚠️ 商品填错活动页会在该页查不到记录，可能误报“商品从活动中消失”，务必对应准确。
3. **活动截止时间（activityDeadline）**：按活动维度控制报警的总开关。截止前，活动下线/清退、状态异常（非「已发布设定」）、草稿、价格/库存异常、商品消失等都会钉钉提醒对应负责人；**过了截止时间后该活动的一切异常自动停止报警**（网页管理里显示「已过活动截止时间，停止异常监控」）。只写日期（如 `2026-09-10`）按当天 23:59:59 截止，也可精确到 `2026-09-10 18:00`；留空表示一直监控。另外：新版活动商品管理页的行内没有报名时间列，此前这类行会被误判「不在监控时间范围内」而不报警——现已修正为：行内无报名时间时按当前状态纳入监控（行内状态是实时事实，不受监控开始时间限制）。
4. **无界面服务器登录**：`shop-login.js` 需要有头浏览器。两种办法：
   - 本地有图形界面的机器上运行 `node shop-login.js shop01` 登录成功后，把 `profiles/shop01` 整个目录上传到服务器对应路径；
   - 服务器上用 `ssh -X` 转发显示，或装 `xvfb` 后把 config.json 中 `headless` 设为 `false` 并手动操作。
5. **状态白名单模式（默认开启，推荐）**：商品行状态只有是「已发布设定 / 报名成功 / 审核通过 / 报名进行中 / 活动中」才视为正常，其余任何状态——草稿、清退、异常、撤销报名、未生效等——一律报警，比逐个猜异常关键词可靠。报警文案会带上识别到的当前状态（如「当前状态为草稿」）。如后台还有别的正常状态词，加进 `normalStatusWords`；想回到旧的关键词模式，把 `statusWhitelistMode` 改为 `false`。
6. **淘宝风控**：千牛/淘宝登录风控比拼多多严格（滑块、扫码、设备验证、会话有效期更短）。首次登录务必人工完成所有验证；之后如果报警提示“登录状态已失效”，重新执行 `node shop-login.js <店铺编号>` 即可。建议 `intervalMinutes` 不要小于 15，避免高频访问触发风控。
7. **首次使用先跑 `node monitor.js --once` 并查看 `logs/monitor.log`**：确认每个商品都能查到记录、`statusText` 与后台实际状态一致。页面 DOM 定位采用平台无关的打分算法，若个别商品识别失败，日志中会有 `error` 说明和 `logs/error-*.png` 截图，可按截图调整 `offlineWords`/`successWords` 等关键词配置。
8. **价格/库存校验是可选增强**：只有填写了 `expectedPrice` 或 `minStock` 才启用；行内识别不到价格/库存时会在日志告警但不误报钉钉。

## 常见问题（Windows 部署实测）

1. **钉钉收到“无法连接本机 Chrome 调试端口”**：说明某个店铺的监控专用 Chrome 窗口被关了。程序会**自动单独重启掉线店铺的窗口**（只重启那一个，不影响其他店铺）并重连，一般无需处理；如果自动重启也失败，可手动只重启该店铺：`node start-chrome.js 店铺编号`（如 `node start-chrome.js cqh`），或在程序目录命令行执行后保持窗口打开。注意监控期间不要手动关闭这些窗口。
2. **钉钉收到“店铺名称校验失败”**：先看 `logs/error-*.png` 截图。
   - 截图是千牛/淘宝登录页 → 登录态没有保存成功：重新运行 `node shop-login.js shop01`，用手机千牛或淘宝 APP 扫码，等浏览器里真正进入卖家后台、能看到店铺数据后，再回终端按回车。
   - 截图是正常后台 → 店铺名和配置不一致：`shop-login.js` 终端输出里会打印“页面识别到的店铺候选”，把 config.json 的 `name` 改成与它一字不差；单店铺场景也可以把 `verifyShopName` 改为 `false`。
3. **店铺名不要带【】等括号**，必须与后台显示的文字完全一致（程序会自动去掉首尾装饰括号，但仍建议填干净的名字）。
4. **Windows 上 profileDir 建议留空 `""`**：程序会自动使用安装目录下的 `profiles/<店铺编号>`。不要保留模板里的 `/home/admin/...`（那是 Linux 路径示例）。
5. **PowerShell 报“禁止运行脚本”**：改用 cmd 执行 npm 命令，或执行一次 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 后重开窗口。
6. **登录态有效期**：淘宝会话一般几天到几周不等。配置店铺账号密码后，过期时监控会自动尝试密码重登（见“免扫码”一节）；未配置时收到“登录状态已失效”报警，重新跑一次 `node shop-login.js <店铺编号>`（内置模式）或在监控专用 Chrome 窗口里登录（cdp 模式）即可。
7. **磁盘占用治理**：程序目录变大的主要来源是各店铺 Chrome 用户目录（chrome-profile-*）里的网页缓存，不是日志。已内置三层防护：① 日志和错误截图只保留 48 小时，每小时自动清理，monitor.log 超 20MB 自动轮转；② 启动监控 Chrome（start-chrome.js）和掉线自动重启时，会先清掉该店铺的网页缓存（Cookies/登录态不动）；③ Chrome 启动参数已限制磁盘缓存上限 100MB。想立刻瘦身：关闭所有监控 Chrome 窗口，双击「一键清理缓存.bat」（或 `node cleanup-now.js`），会打印每个店铺释放了多少空间。
8. **「最近检测时间」长时间不更新**：先看「检测状态」页底部日志是否在滚动。程序已内置三重防护——钉钉发送 15 秒超时、单店铺检测超过 `shopTimeoutMinutes`（默认 12 分钟）自动跳过、通知发送失败不再阻断结果保存——正常不会再冻结。如果日志本身停了，说明监控进程已退出：Windows 上检查电脑是否**休眠**（电源设置里把睡眠改为“从不”）、命令行窗口是否被关掉，然后重启 `node monitor.js`。另外注意：30 分钟间隔是“一整轮跑完后再等 30 分钟”，12 个店铺一轮本身要跑 20~40 分钟，所以相邻时间戳差 50~70 分钟是正常的。
